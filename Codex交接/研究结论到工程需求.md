# Codex 研究交接：当前结论（草案，非立即实施命令）

日期：2026-11-03｜来源：SWE-Perf §3–4、PerfAgent §III/IV、ShinkaEvolve 官方 README、OpenHands SDK 官方 README。

## 当前可确定的架构要求
1. 通用程序优化为主线，ParaLedger 为可插拔应用/测试场景；不得把系统硬编码成 Slurm/RDMA 专用优化器。
2. `Agent` 提供优化规划与 Patch 生成；Benchmark 和 CorrectnessGate 必须在 Agent 控制外独立执行验证。
3. 每个候选都能追溯到 `base_commit`, `diff`, `environment`, `workload`, `test`, `profiler_artifact`, `runtime_samples`, `status`。
4. 正确性与性能分开评价；保留最佳已验证版本，支持回滚/隔离工作树。
5. 预算受限，支持失败、超时、噪声大、测试不一致、评价器篡改的拒绝情况。

## 需要先做审计，而不是直接修改
- 看当前 FinePerf、Runner、Report、Benchmark、Agent 层已有接口。
- 生成一张 `existing -> desired` 功能矩阵：保留/适配/缺失/删除（谨慎）。
- 不要为重现研究草图而重写既有测试系统。

## 可独立拆出的任务（需要用户确认后实施）
- T1：建立 `OptimizationTask`/`PatchEvaluation` 的 JSON Schema 与验证测试。
- T2：实现 Mock Benchmark 及三层 Apply/Correctness/Performance 门禁。
- T3：Profiler output → 结构化摘要；保留 provenance / confidence。
- T4：候选 Patch 隔离与最优正确版本管理。
- T5：同预算下比较单路径反馈与多候选搜索的试验框架。
